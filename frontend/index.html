How to Configure HAProxy Intelligent Read Routing with Primary-Replica MariaDB

1. Configure MariaDB GTID-based replication between the primary writer and secondary reader instances.
2. Configure HAProxy with two distinct backend listeners: Port 3307 for writes (routed strictly to primary) and Port 3308 for reads (load-balanced with roundrobin).
3. Configure health check scripts checking `SHOW SLAVE STATUS` to remove lagging replicas automatically.
4. Position Redis in front of read replicas to cache repetitive query sets with TTL invalidation.

Glossary of Core Engineering Terms

Retrieval-Augmented Generation (RAG):
An AI architectural pattern that enhances LLM generation by retrieving relevant context from vector databases (e.g. ChromaDB) before generating a response, preventing hallucination.
Low-Rank Adaptation (LoRA):
A parameter-efficient fine-tuning technique that freezes base model weights and trains low-rank decomposition matrices, dramatically reducing memory and compute requirements.
Model Context Protocol (MCP):
An open standard for connecting AI models to external tools, databases, and contextual services in a unified, secure manner.
HAProxy Read Routing:
The practice of using HAProxy as a database proxy to intelligently steer write operations to a primary master and load-balance read queries across multiple read replicas.
